# 115资源网站分享监控修正（Windows，2026-10-10）

## 本次查明的问题

旧版本确实存在扫描缺陷。不太灵的fetchCloudCatalog返回total/limit，分享扫描却只读取hasNext，导致第一页被当作末页；年份条件在第一页可能全部被跳过，于是显示“检查0部”，却没有继续下一页。另外，分享扫描沿用了磁力的资源大小、画质和更新时间限制。许多网盘分享不提供这些字段，目录本身也不一定有大小，因而可能被当成不合格资源，且没有具体跳过日志。

修正：根据total/limit计算不太灵下一页，空页不继续请求；使用原有原生查询组合展开多个年份、类型条件，不直接把数组拼成无效查询。首页轮换及后续页断点保留，每轮按用户配置的页数逐步扫描。刷新站点资源读取，减少缓存导致的新分享延迟。

## 使用

1. 登录115和需要登录的资源网站。
2. 在该网站自动监控页保存影片类型、年份、地区等条件，无需开启磁力提交。
3. 进入左侧“115分享监控”，创建任务，选择资源网站、指定115保存文件夹、检查间隔，并勾选“开启自动监控”，保存任务。
4. 开启“自动保存115分享链接”总开关。它只允许分享功能运行，不自动创建任务。已保存并开启的任务会按间隔自动扫描，也可点击任务“立即检查”。磁力总开关可以保持关闭。
5. 查看同一页的运行日志及任务上次/下次检查时间，确认发现了115分享，并收到“115已接受转存；目标：…”反馈。

新版默认沿用影片条件，但不会默认套用磁力资源的大小、画质、更新时间限制。若确实需要这些限制，可在分享任务中勾选“额外沿用资源大小、画质、更新时间限制”。缺失信息可能导致拒绝，此时日志会给出筛选原因。旧任务未配置此新选项时使用默认关闭，扫描签名变化会重置旧断点。

此功能读取资源网站可访问到的115分享地址，解析提取码，读取115分享文件清单，再向每个任务指定的目标文件夹提交转存。已接受的分享跳过，不重复转存。这里只监控新分享，不追踪已转存分享内部后续新增的文件。BT影视现有解析器没有网盘资源时，会记“未提供可读取的网盘资源”，不声称已经转存。

指定文件夹和账户会在每轮检查。目录失效、账户不符、登录/验证失败会有日志，停止对应轮次，不回退根目录。接口“已接受”不等于逐文件核验完成。提交超时、缺少明确结果时保留待核对记录，不自动重复提交；核对115目标目录后再标记已转存或允许重试。

## 新日志

分享监控页面持久化最近500条日志，并实时推送，包括任务保存/启用状态、扫描开始、分类及页码、返回影片数/下一页、影片筛选跳过、资源读取失败、没有网盘资源、发现115分享、其他网盘跳过、已处理或待核对跳过、空分享、资源限制不通过、提交项目数量及目标、转存反馈、轮次汇总和下次检查时间。

支持按任务筛选及导出最近日志。运行日志页面新增“115分享监控”分类，来源网站在日志详情中保留。运行日志的完整当日下载仍可使用；分享页导出仅导出最近500条中的所选任务。日志不写入Cookie、访问令牌或提取码参数。

## 开发与验证

main.js修正share115Adapter：原生查询展开、分页计算、默认分享限制独立、可选严格限制、站点资料刷新；share115-monitor.js增加逐步日志、统计、资源错误说明、持久化日志；share115-renderer.js增加可选限制、任务时间、实时日志、任务筛选及导出。全局日志来源新增share115。观影、聚影云资源读取支持fresh选项；七味分享解析扩展115cdn、anxia等标准域名。

tests/test-share115-adapter.cjs调用实际适配器代码验证分页、查询组合和缺失元数据处理，并完整模拟“第一页年份不匹配、115链接只在第二页出现”的任务：确认扫描第二页、读取分享、提交到精确指定目录、持久化全过程日志。已有分享模块测试继续覆盖接口分页、账户绑定、提交前落盘、重启去重、结果不明和取消。新增Electron页面测试验证日志、按任务筛选、导出入口、指定目录载荷及默认资源限制独立。原有30项回归通过。

本次没有使用真实用户账户发起转存；服务器访问权限、会话验证和实际云盘文件结果仍需用户登录后试运行确认。Windows完整便携EXE从最终源码打包，实际EXE内app.asar代码与源码核对。源码ZIP包含全部电脑版源文件、锁定依赖、测试、开发说明，不含个人Data。

历史Data继续合并到本机新版目录，原始快照保留。正在运行的旧版本可能锁住Cookies，未能复制的项目见Data合并报告.json；这些会话仍需要退出旧版后补齐。本次保存目录不变，不在用户云盘执行测试性转存。
