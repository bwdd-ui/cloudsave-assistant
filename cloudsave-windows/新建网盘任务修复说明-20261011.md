# 新建网盘保存任务按钮修复

问题原因：“新建任务”原来仅执行form.reset()，已为空的表单没有可见变化；有已选目录或网盘时还会清空它们，导致用户以为按钮失效。

当前行为：点击“＋新建任务”显示“新建网盘保存任务”标题，生成可修改的任务名，聚焦名称输入框，并显示操作提示。保留当前网站、115/光鸭选择、目标目录、共用筛选，清除编辑中的任务ID，自动监控默认不勾选。点击“创建任务”才持久保存，不会因为点击新建就自动发起云盘保存。

编辑已有任务时按钮显示“保存修改”；从编辑状态点击新建，会创建独立的新任务而不覆盖原任务。创建完成后参数仍保留，便于继续创建其他任务。需要不同目标目录时重新选择；需要自动运行时勾选开启自动监控后创建。登录和目录有效性检查仍然执行，错误会显示在表单提示中。

修复版EXE放在原“云存助手-光鸭共用筛选版-20261011”交付目录，与原程序使用同一个Data。未修改、覆盖或清空Data，也未再次复制被占用的浏览器Cookies。先退出原程序（包括托盘后台实例），再运行“云存助手-磁力采集与Excel版.exe”。旧EXE保留，最新源码ZIP包含本次修复。旧版迁移报告中尚未复制成功的会话文件不会因为UI修复自动补齐。

测试：test-new-cloud-task-ui.cjs用真实Electron DOM点击新建/创建/编辑按钮，验证状态变化、焦点、目录与条件保留及两个独立任务；test-inline-share-ui.cjs和test-guangya-shared-ui.cjs验证原有同页布局、日志、筛选与光鸭目录选择。未运行实际客户端或对真实网盘发起保存。本次只修改界面逻辑与测试模拟，115和光鸭请求、筛选及调度后端保持原实现。
