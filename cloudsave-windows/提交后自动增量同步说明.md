# 云存助手电脑版 · 提交即增量更新版20261009

在上一版全量缓存、五站分钟筛选、目录核对功能基础上，新增提交成功事件触发115云下载增量更新。本次只更新Windows完整EXE，不改变NAS与安卓包。

## 使用和更新

退出旧程序，把新EXE放在原EXE目录并保留完整Data文件夹。原缓存、账号、默认文件夹与监控配置继续使用。离线任务同步区域显示“提交即增量更新版20261009”。

手动提交、批量离线、五个自动监控的新磁力或电驴任务，得到115成功接受回执并保存本地记录后，自动触发增量同步，通常约3秒启动。连续提交合并处理，持续提交时两轮启动至少间隔5秒；不是每条磁力都重复发起一轮扫描。同步期间又有新任务接受，则当前读取完成后再补一轮，避免被正在运行的旧快照漏掉。

若定时或全部同步已在运行，先等待其缓存写入完成，再执行新的增量读取。提交线程不等待同步线程，避免与后台保存目录核对的串行操作互相等待。不会重新提交任务，也不会自动触发全部同步。

如果115列表暂未显示刚接受的任务，或网络失败，最多再进行两次延迟重试，间隔至少15秒，失败保留旧缓存。缓存历史不清空，磁力键去重不会重复累加。日志以“115”网站来源记录事件及同步结果。

“全部同步”仍可用于建立完整缓存，普通“立即同步”仍为增量。提交事件不受原定同步间隔限制。原“自动同步”复选框更名为“定时同步”：关闭定时同步以后，提交成功触发的更新仍会运行，符合本次要求。

事件增量主要读断点之后的新列表，通常只需新记录所在的一两页，实际页数取决于新增量。更老的下载中/失败任务不会在每次提交时重复轮询；到设定的同步间隔后仍会分批核对。独立的oldStatusSyncedAt防止连续提交不断刷新syncedAt而使旧状态永远得不到核对。

重复链接被本地跳过、115明确返回重复任务或提交失败/未确认，不触发成功事件。在其他软件或115网页直接新增的任务仍靠定时/手动同步发现。本软件关闭后不能同步；尚未开始的事件计时器不持久化，正常启动后的既有自动同步或手动同步会读取新增记录，定时同步关闭时可点一次立即同步。

## 实现

- main.js：submitMagnet统一成功分支保存队列并flush后调用cloudSubmitSync.trigger(uid,magnetKey)。所有软件提交入口共用此函数；重复/错误分支不触发。
- cloud-submit-sync.js：三个秒合并窗口、至少五秒启动间隔、等待已有缓存同步、按revision记录扫描期间的新提交、最多两次重试、任务键可见性检查、账户和退出保护。调用syncCloudDownloads(true,{checkOldTasks:false})，仅强制增量，full仍为false。
- cloud-download-cache.js：增加checkOldTasks选项及oldStatusSyncedAt，事件读取不重复查询旧状态，但旧状态达到设定间隔仍核对。Data/cloud-download-state.json保持version1兼容。
- index.html/renderer.js：定时同步名称、提交自动更新说明、新版本标识。云下载状态及数量仍由现有事件实时推送到界面。
- package.json：将cloud-submit-sync.js加入build.files。
- 退出流程：取消提交事件计时器，等待已启动的同步、离线操作和写入完成。

此前完整功能说明见同源码包“全量缓存分钟筛选与目录修正说明.md”。
