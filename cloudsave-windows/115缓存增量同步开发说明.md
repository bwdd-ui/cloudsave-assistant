# 电脑版115缓存增量修正版 · 20261009

本次仅更新Windows完整Electron版，安卓和NAS包未同步修改。保留当前五个资源库、自动监控、123分享任务、网页登录、七味资源分类/原始更新时间、原生分页等功能。

## 修改原因与行为

之前生产逻辑会保留历史任务，但每次重新读取整个所选24小时窗口。这属于窗口增量，并没有使用上次同步断点；如果大部分任务都在24小时内，读取量仍接近全量。界面进度还显示远端总页数，容易误认为正扫描所有页。

新版在账户缓存已有有效增量基线且范围未改变时，读取起点为max(本轮开始时间-范围小时数, 上次成功同步时间-5分钟)。第一次同步或者范围扩大/改变，仅读取所选范围。API按任务添加时间倒序返回，到达起点所在页后停止，不请求后面的历史页。单页返回可能包含更老记录，它们不会作为新任务加入，已有缓存仍保留。重叠区按磁力哈希去重，不重复累加。

“立即同步”只绕过同步间隔，不清空缓存，不将增量变为全量。缓存按115 UID隔离，重启会读取Data里的缓存和时间断点。列表格式、时间字段或排序异常时失败，不自动降级为全量扫描。

列表按添加时间排序，旧任务即使完成也不一定移到新记录前面。因此每轮对缓存中尚未完成、失败或未知且有40位磁力哈希的任务，最多进行20次单条状态查询，按pendingCursor轮询。已在增量列表读取的任务无需重复查询；已完成历史任务不再轮询。单条查询失败/没有确认哈希或状态时保留旧结果，不执行历史列表扫描。缓存计数是累计记录及最近获知状态，不保证和115网页此刻的全部统计完全一致；任务多时状态轮询需要数轮。HTTP/无哈希任务保留最近列表结果，不进行单条状态查询。

超出选定24小时范围且从未缓存的新任务不会自动补扫。可手动选择更大范围（48小时或7天）并保存后同步；已有历史缓存不删除。远端删除任务也不自动删除累计缓存，这是增量历史缓存，不是实时全库镜像。

## 更新方式

退出旧程序，把新EXE放在原程序EXE所在目录后运行，保留原目录的完整Data文件夹。不要仅将EXE放到新空目录，否则那里没有已有账号、缓存和断点。也可以把完整Data随新EXE一起复制到新目录；密钥等文件必须一起保留。界面“离线任务”同步状态显示“缓存增量版20261009”，可确认启动的是此版本。

默认每60分钟同步，可自定义1–10080整数分钟。自动监控使用同一份本地缓存和同步间隔；手动同步不会改变自动间隔设置。首次若无缓存，读取24小时的记录，并不会获取更老的全部历史。

## 修改文件

- cloud-download-cache.js：同步断点、五分钟重叠、去重累计、旧状态最多20条轮询及游标、写入完成再发布新快照、进度及统计字段。
- main.js：接入现有get_user_task单条接口，明确没有列表回退；等待BufferedJson.flush后完成同步；IPC暴露实际列表页数及旧状态核对数。
- renderer.js：显示版本标识、累计缓存、本次实际读取页数/条数、新增/变化、旧状态核对和失败未确认数量。不再用远端总页数作为目标进度。
- tests/test-cloud-checkpoint-cache.cjs：3500缓存/远端100页模拟、断点、重启、间隔、旧状态轮询、故障原子性。
- tests/test-cloud-checkpoint-ui.cjs：真实Electron离屏渲染UI验证，使用mock接口，不访问真实115账号。
- tests/test-cloud-sync-v4.cjs：核查时间更新同时保证未变化状态不计为变化。

Data/cloud-download-state.json保留version1兼容旧数据。每个账户accounts[UID]：tasks{磁力键:任务}、currentKeys、counts、syncedAt、count、readCount、fetchedCount、pageReads、statusChecked、statusErrors、pendingCursor、added、changed、incremental、checkpoint、lookbackHours、rangeStart。

syncedAt采用本轮开始时间，避免长时间读取过程中添加的新任务落入断点空隙。写入使用原有BufferedJson的临时文件重命名并等待flush；写入失败不发布内存成功断点。任务checkedAt表示最新成功核查时间；同状态重复核查不计changed。

## 验证

30个现有回归测试文件通过；新增大缓存断点测试、24小时边界测试、分钟调度测试、同步表单UI测试、新增断点统计UI测试通过。模拟3500条旧缓存、远端100页时只读取1页，并轮询20条旧任务状态；重启后复用断点。列表/写入故障保留已有缓存。已从实际便携EXE中提取app.asar，核对其中三个运行文件与最新源码完全一致。

此次没有使用真实115账号执行网络同步，单条接口可用性及真实任务分布仍需在实际账号运行中确认；失败会保留旧状态，并在UI显示未确认数量。测试结果不能理解为所有3500条远端任务都已实时核查。

## 构建复现

Windows x64，Node24、Electron44.5.1、electron-builder26.0.12。源码包包含package-lock.json、运行源码、测试及本说明，不包含node_modules、dist、Data、账号或密钥。

在cloudsave-windows目录：

```powershell
npm ci
node tests/run-tests.cjs
node tests/test-cloud-checkpoint-cache.cjs
node tests/test-cloud-recent-sync.cjs
node tests/test-cloud-sync-schedule.cjs
node_modules/.bin/electron tests/cloud-sync-ui.cjs
node_modules/.bin/electron tests/test-cloud-checkpoint-ui.cjs
node_modules/.bin/electron-builder --win portable --config.electronDist=node_modules/electron/dist --config.win.artifactName=CloudSave-CheckpointCache-20261009.exe
```

运行入口main.js，渲染器renderer.js，IPC由preload.js桥接。package.json build.files列出运行文件，可据此复建完整电脑版。npm及Electron运行依赖需联网获取，源码包并非全部依赖的离线镜像。
